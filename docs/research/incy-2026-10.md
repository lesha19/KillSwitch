# INCY vs KillSwitch (2026-10-10)

Scope: what the INCY apps (github.com/INCY-DEV) do, compared with KillSwitch 0.14.2. Complements
`mullvad-ivpn-gap-2026-10.md`. Issues #8-#21 are already planned and are only referenced, not repeated.

## 0. Limits of this research

- The INCY apps are closed source. The org has only: `incy-docs` (provider/developer docs, mkdocs, served at
  docs.incy.cc), `incy-platforms` (README + release binaries; no changelog text, release bodies are one line),
  `incy-link-encoder` (+PHP port), `incy-tv-relay`, `incy-icons`, `.github` profile. So the inventory comes from
  the README, the provider docs and incy.cc (home, roadmap). Desktop UI details (graphs, connection log, server
  groups, kill-switch internals, TUN setup on macOS) are NOT documented publicly; those rows are marked "?".
- The desktop client is "pre-alpha" per README (v3.8.8, 2026-09-22); macOS DMG for arm64 and Intel plus a Mac
  App Store listing shared with iOS/tvOS. incy.cc roadmap lists "Native macOS with Network Extension" as planned,
  "On-Demand rules (Wi-Fi/cellular/schedule)", "Auto server choice by ping and packet loss", "Backup and sync of
  settings" as not done yet.
- Core: Xray-core (README: "built on Xray-core"); iOS/macOS tunnel uses hev-socks5-tunnel; desktop in TUN mode
  has Xray own the TUN device; AmneziaWG engine amneziawg-go v3.1 (mobile only). Roadmap: "Incycore" native
  library replacing the xray subprocess.

## 3. Ranked NEW ideas (not in #8-#21)

1. Provider notice from the subscription: read `announce` / `announce-url` (also `#announce:` lines and
   base64: values), `support-email`, and show them on Home as a dismissible notice with a button. KS already
   reads profile-title / support-url from the same response. S, high value for StorkVPN-style providers
   (maintenance warnings reach users without a Telegram post).
2. URL scheme commands and import: `killswitch://connect`, `disconnect`, `toggle`, `add?url=<sub>` (confirmation
   dialog), mirroring `incy://`. Lets a provider put "Open in KillSwitch" button on a site/bot, and makes
   Shortcuts/Alfred scripts trivial. Complements CLI #12. S-M.
3. QR: scan a QR from the screen or clipboard image to add a subscription/server, and show a QR of the sub or a
   server link. Both INCY and every competitor have it. M.
4. User-owned named routing profiles (import by URL/QR, auto-update by URL with interval, `Name`-based
   replace, error flag), kept strictly user-chosen so #8's "app adds no rules" rule still holds; the profile
   can only add DIRECT with admin approval as today. Follow-up to #8, not a replacement. L.
5. Sort control and ping options in the server list (sub order / ping / name, auto-ping after sub refresh,
   bars display). Small extension of #13. S.
6. `hide-url` header support: hide the subscription URL in Share/Copy/diagnostics/backup when the provider asks.
   Also protects the URL in #15's problem report. S.
7. Optional provider-supplied routing hint: accept `routing`/`autorouting` header (INCY profile JSON or Clash
   rule-provider URL) and show it in the #8 transparency view as "provider routing", plus `routing: off` as a
   provider switch. Only after #8 lands. M.
8. Geo data hygiene: check `.sha256` side file before downloading geoip/geosite (skip when unchanged), abort
   after 3 minutes, show a per-file error. Optional custom geo URL for users who want runetfreedom/Loyalsoldier
   lists. S-M.
9. DNS hosts table (manual `domain -> ip` records) inside KS-DNS, useful for DoH bootstrap and local services.
   Extends #14. S.
10. Share the tunnel over LAN (SOCKS5/HTTP on mixed port bound to LAN with allow-list of client IPs), the
    "hotspot sharing" INCY advertises. Needs pf rules for the LAN port and must not leak when the tunnel is down. M.
11. Proxy-only / system-proxy mode. Not recommended for a kill-switch product; only as an explicitly labelled
    "no kill switch" mode. M, low priority.
12. `llms.txt` / `llms-full.txt` for KillSwitch docs (INCY serves one plus GitMCP) so assistants can answer
    setup questions. S.
13. Deep-link obfuscation like `crypt1` for sharing subscription links in Telegram. INCY itself says it is
    obfuscation, not security. M, low.

Not worth taking: Premium-API provider features (lite mode, banners, themes, push, admin-by-HWID, fallbackHosts
from the encrypted API), TV relay, Wi-Fi/Mobile-only server markers, per-app proxy via headers, iOS memory mode,
app icon sets.
