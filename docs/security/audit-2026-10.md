# Security audit 2026-10: root side of KillSwitch 0.12

- Scope: everything that runs as root or decides what root runs: `Helper/ks` (passwordless sudo
  and the watchdog), `Helper/install.sh`, `Helper/uninstall.sh`, the generated mihomo config, and
  the app code that builds admin commands (`AdminScript`, `Onboarding`, `scutil --nc stop`).
- Base: 0.12 (13), `fe54fe4`. Fixed in 0.12.1 (14), branch `security-0.12.1`.
- Tests: `Helper/tests/*.sh` (new: `env.sh`, `root-files.sh`, `args.sh`) and the Xcode unit tests.

## Findings

| ID | Severity | Location | Finding | Fix |
|---|---|---|---|---|
| KS-01 | Critical | `Helper/ks` (top), `install.sh` sudoers | `ks` runs as root through passwordless sudo but kept the caller's environment and called tools by bare name. macOS's sudoers keeps `HOME`, so root's `curl` read the user's `~/.curlrc`; `PATH`, `IFS`, curl/TLS/proxy/perl variables were not reset either. | `b1eb67e`, `115736c` |
| KS-02 | High | `Helper/ks` `core_generate`, rule-providers | Provider names were listed line by line from plutil's XML. A name with a line break was never listed, so never checked (type allow-list, `path` removal, download proxy), yet copied into the config. | `e73dfb6` |
| KS-03 | High | `Helper/install.sh` (geodata) | As root, install copied `geoip.metadb` from dropweb's folder in the user's Library (user-writable) into the core's directory, for the root core to parse. | `604d9ff` |
| KS-04 | Medium | `App/Core/AdminScript.swift`, `Onboarding.swift` | The admin prompt's root shell inherited the app's environment, which any process of the user can set (`launchctl setenv`). With `BASH_ENV` set, `/bin/bash install.sh` ran a file of the caller's choice as root once the admin typed the password. | `d4978db` |
| KS-05 | Medium | `Helper/ks` `core_import`, `core_generate` | The copy of the profile and the generated config (server passwords) were written 0644 and only then set to 0600. `core/` is 0711, so a reader who knew the names could catch them. | `9b9eaa1` |
| KS-06 | Low | `Helper/install.sh` | The user name written into `/etc/sudoers.d/killswitch` was not checked. `visudo` rejects bad syntax, but not valid lines such as `ALL`, `%group` or `#uid`. Exploiting this needed the admin password. | `cbde423` |
| KS-07 | Low | `Helper/ks` dispatch | The passwordless commands relied on sudoers alone for their arguments: `state`, `probe`, `on`, `netrestore` and `core state/on/off/proxies` ignored extra arguments. | `a357526` |
| KS-08 | Low | `App/Core/OtherVPN.swift` | The service id passed to `scutil --nc stop` could be any 36 hex-or-dash characters, including a string starting with `-`. | `15a4ca3` |

### What changed

- KS-01: the first lines of `ks` (`ks_clean_env`) set a fixed `PATH`, `HOME=/var/root`, `LC_ALL=C` and
  `TMPDIR`, reset `IFS`, and unset curl, TLS, proxy, perl, locale and loader variables.
  The shebang is `#!/bin/bash -p`, so bash ignores `BASH_ENV`, `ENV`, `SHELLOPTS` and exported
  functions before line 1. Every `curl` call starts with `-q`. sudoers gets per-command `Defaults`
  for `ks`: `secure_path`, `env_reset`, `env_keep -=` for `HOME`, `MAIL` and the locale variables,
  and `env_delete +=` for `HOME CURL_HOME BASH_ENV ENV LC_ALL`. `install.sh` and `uninstall.sh` fix
  their own `PATH` and `HOME`.
- KS-02: the providers are checked in JSON::PP on the decoded object. Names must match
  `^[A-Za-z0-9_-]{1,64}$`; only `http` (with an http(s) url) and `inline` are allowed; only known
  fields are kept; `path` is dropped; `proxy` defaults to `KS-DNS`. A proxy named by the profile is
  part of the DIRECT signature, so `refresh` needs the admin password for it. Before these checks,
  every key at any depth of `proxies`, `proxy-groups` and `rule-providers` must contain no control
  characters, and every rule must be a one-line string (fail closed). `direct_sig` treats an http
  provider without a proxy as a direct download.
- KS-03: `geoip.metadb` is fetched from the same pinned meta-rules-dat commit as `geosite.dat`,
  checked by sha256 (`fetch-geodata.sh`), shipped and signed in the app bundle, and installed only
  from there (root:wheel 0644). If the bundle has no copy, a stale one from dropweb is removed.
  `release.sh` checks both files against the pins. No root script reads a path under a user's home
  (`root-files.sh`).
- KS-04: osascript runs with `PATH=/usr/bin:/bin:/usr/sbin:/sbin` only. Bundled scripts run as
  `/bin/bash -p`.
- KS-05: these files are written under `umask 077`, and leftover files are removed before writing.
- KS-06: install accepts only a plain name of an existing account with uid ≥ 500.
- KS-07: `passwordless_args_ok` accepts exactly the forms the app sends: no extra arguments,
  `select`/`delay` names without control characters (max 256 bytes), and one absolute path for
  `refresh`.
- KS-08: only the 8-4-4-4-12 UUID form is accepted.

## Verified OK

- mihomo controller: only `external-controller-unix` exists, in `core/ctl/` (root, 0700). The
  profile's `external-controller`, `secret`, `external-ui`, listeners, ports, `tun`, `dns` and
  `interface-name` never reach the config (`core-config.sh`: exact top-level keys).
  Since ADR 0013 the profile's `dns` and `sniffer` reach it only through an allowlist of keys with
  validated values (`fake-ip-filter`, `nameserver-policy`, `direct-nameserver`, `respect-rules`;
  no `system`/`dhcp://` resolvers; `core-routing.sh`).
- Core process: started by launchd from root-owned paths with a root-owned config, gid `_ksvpn`
  and umask 077. pf lets it reach only the server addresses (or everything with `coredirect=1`).
  Since ADR 0013: everything only while `core/egress` names a reason (the subscription's DIRECT
  rules or DNS policy, or the user's programs without VPN); `coredirect` is gone.
- Files root creates: `/Library/KillSwitch` (0755), `core/` (0711) and `ctl/` (0700) are
  root-owned, so a user cannot plant a file or symlink at the fixed names there. On macOS, `mktemp`
  ignores `TMPDIR` and uses root's per-user directory (root, 0700). Root code does not use `/tmp`.
- `core import`/`refresh` read the source file with the caller's rights (`sudo -u $SUDO_UID`),
  capped at 20 MB. `refresh` cannot add server names or addresses, and cannot change what goes
  DIRECT (`refresh_check`).
- `core select`/`delay`: names are percent-encoded byte by byte, and the JSON body is built by
  plutil.
- `netrestore` only re-enables services that `ks` itself recorded as disabled, and refuses while
  the watchdog is loading its rules.
- `probe`: fixed addresses and port 443, run as the core group, no data sent.
- Admin prompt: every argument goes through `quoted form of` (`AdminScriptTests`). Before root
  runs a bundled script, the bundle signature is checked.
- `scutil --nc stop` runs as the user, by absolute path, with an argument array and no shell.
- Server addresses from Happ's and dropweb's files are read by the app as the user. Only plain IPs
  go into admin commands, and `install.sh`/`ks` validate them again.

## Open points

- The app checks the bundle signature and only then has root copy `ks`/`mihomo` out of the bundle,
  so there is a short window between the two. A process that can write to the app bundle can
  replace the app anyway. Copying into a root-owned staging directory before verifying would
  close the window.
- `ks core import` via the admin prompt has no `SUDO_UID`, so root reads the path itself. The path
  is the app's own temporary file, and the content is checked as for refresh.
- Existing installs keep their old sudoers until `install.sh` runs again. The changed `ks` makes
  the app offer «Восстановить службу…» once.
- With `LC_ALL=C`, the 256-character limit on proxy names is now 256 bytes.
- Rule providers with fields outside the allow-list are now refused; confirm against real
  subscriptions.

## Addendum 0.13: XPC daemon and new commands

Reviewed under the same rules before 0.13 (integration of `helper-xpc` and `features-0.13`):

- The XPC daemon `KillSwitchHelper` (ADR 0010) runs `ks` and the bundled scripts with
  `HelperCommand.environment` (only the system `PATH`, equal to the password prompt's) and the
  scripts with `bash -p`; `ks` then applies `ks_clean_env` and `passwordless_args_ok` as with sudo.
  The user it passes to `install.sh` follows `valid_user`. Tests: `HelperCommandTests`.
- New passwordless command `ks core traffic`: exact arguments in sudoers, `passwordless_args_ok`
  and the daemon's passwordless set (`Helper/tests/args.sh`, `HelperCommandTests` compare them with
  the sudoers line both ways). It prints two byte totals through `core_api` (`curl -q`).
- `ks set adblock` stays behind the password / authorization right like every `set`: it only adds a
  REJECT rule from the shipped geosite.dat, but it changes what the core does.
- The watchdog's wider `foreign_tuns` reads only `ifconfig` and `netstat`; `fetch-geodata.sh`
  takes both pinned files from our releases first, every `curl` with `-q`, each checked against its
  sha256. `Helper/tests/root-files.sh` and `env.sh` pass on the merged tree.
